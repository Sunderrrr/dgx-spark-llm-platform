# Configuration

Everything the deployment reads from the environment, and everything the admin
can change at runtime from the Admin configuration tab. For the install itself,
see [deployment](deployment.md).

## Secrets first

> `.env` is **gitignored** — no secret is committed. `.env.example` holds only placeholders.
>
> A secret never goes in git — messages included. Three guards cover it:
> `scripts/pre-commit-check.sh` (installed as `.git/hooks/pre-commit`, refuses the
> commit — message, staged diff, forbidden filenames, and any LIVE value of
> `.env`), `scripts/pre-push-check.sh` (same on the pushed range) and the CI
> `secrets` job. Real credentials go only in `.env` and local-account passwords
> (hashed in `local_users`) — never print a password to output, never write one
> into a tracked file.

## `.env` keys

`docker-compose.yml` injects these into `dgx-portal` / `litellm`. `install.sh`
(via `setup.sh`) generates the random secrets; fill in the rest. See [`.env.example`](../.env.example).
The backend reads its environment in [`config.py`](../dgx-portal/config.py), with two
exceptions worth knowing: `WEBUI_SECRET_KEY` is mapped to Flask's `SECRET_KEY` by
`docker-compose.yml`, and `POSTGRES_PASSWORD` is never read by the backend at all —
it belongs to Postgres and LiteLLM.

| Variable | Purpose |
|---|---|
| `WEBUI_SECRET_KEY` | Flask session signing key |
| `LITELLM_MASTER_KEY` | LiteLLM master key (gateway admin) |
| `POSTGRES_PASSWORD` | LiteLLM database password |
| `LDAP_BIND_PW` | Password of the LDAP bind account (`LDAP_BIND_DN`) used to look users and groups up |
| `RUNNER_TOKEN` | Bearer token between `dgx-portal` and `vllm-runner` (also used for the sidecar control routes) |
| `OCR_URL` | Internal URL of the OCR vLLM container (default `http://ocr:8000/v1`) |
| `VOICE_URL` | Internal URL of the voice container (default `http://voice:8004`) |
| `ASR_URL` | Internal URL of the Whisper transcription container (default `http://asr:8006`) |
| `IMAGE_URL` | Internal URL of the text-to-image container (default `http://image:8007`) |
| `MUSIC_URL` | Internal URL of the text-to-music container (default `http://music:8008`) |
| `COMFYUI_URL` | Internal URL of the ComfyUI video backend (default `http://host.docker.internal:8188`) |
| `PUBLIC_API_URL` | Public API URL shown to users (default `https://api.example.org/v1`) |
| `OIDC_CLIENT_ID` / `OIDC_CLIENT_SECRET` | Authentik `dgx-spark` OIDC app |
| `OIDC_METADATA_URL` / `OIDC_REDIRECT_URI` / `OIDC_LOGOUT_URL` | OIDC endpoints |
| `OIDC_ADMIN_GROUP` | Group granting the admin role (set it to yours) |
| `SESSION_COOKIE_SECURE` | `1` behind an HTTPS proxy (Traefik), `0` for plain-HTTP LAN |
| `KEY_MAX_BUDGET` / `KEY_BUDGET_DURATION` | Default per-account budget (default 200 M tokens / week) |
| `DISCORD_WEBHOOK_URL`, `SMTP_*`, `ADMIN_EMAIL` | Request notifications |

> `next.config.ts` and `lib/sseProxy.ts` read `BACKEND_URL` to reach Flask
> internally; the default (`http://dgx-portal:5000`) matches the compose service name
> and rarely needs changing.
> Note that `host.docker.internal` is **pinned to a fixed address** there rather than
> using `host-gateway` — see [troubleshooting → Docker networking](troubleshooting.md#docker-networking).

### Email (SMTP)

The portal sends emails via SMTP (your SMTP provider, STARTTLS on submission);
without SMTP config every `notify_*` is a no-op and nothing is sent.

```
SMTP_HOST=smtp.example.com
SMTP_PORT=587
SMTP_USER=no-reply@example.com
SMTP_PASSWORD=<app password>
SMTP_FROM=Your platform <no-reply@example.com>
ADMIN_EMAIL=<address that receives the requests>
# Optional: URL of the admin dashboard for the "Open the Admin dashboard" button
# in the emails. If empty, no button is rendered in the HTML template.
ADMIN_URL=https://portal.example.org/admin
# Anti-spam window for "launch a media category" requests (seconds).
MEDIA_REQUEST_COOLDOWN_S=1800
```

Channels: model/budget requests, the maintenance toggle, the media-page
« Demander un modèle » button, the Admin email test, and infrastructure alerts
(launch failure of a model). **A notification never delays the action it
reports** (2026-09-16: a password change took 3.2 s against a dead LDAP
directory — the send now goes out in a daemon thread).

## Token budget model

Budgets are enforced **per account** (a LiteLLM *user*), shared across all of that
user's keys — creating extra keys does not raise the cap. Pricing is set at model
registration time by [`litellm_client.py`](../dgx-portal/litellm_client.py), not in
`litellm/config.yaml`: prompt and generated tokens both count 1 budget unit each.

Default on a running deployment: **200,000,000 tokens/week** per account
(`KEY_MAX_BUDGET` / `KEY_BUDGET_DURATION`, editable in **Admin → token limit**, no
restart). `docker-compose.yml` deliberately overrides both for a **fresh install**
(`0.002` / `1d`, i.e. a nearly exhausted test account) so a new box cannot be
drained by accident before someone sets the real policy. Admins are uncapped. Over
budget, LiteLLM answers **HTTP 429** and the playground turns it into a
`quota_exceeded` notice; the portal shows a banner once an account passes 85%.
Approving a token request grants a preset or custom amount as a time-limited boost
that stacks and reverts to the exact base cap at expiry.

Enforcement details not to get wrong: the blocking envelope is the LiteLLM *user*
object (`max_budget` + `budget_duration`), so a quota write **always sends the
duration** — an omitted duration turns the cap into a lifelong one; `max_budget: 0`
really caps at zero (it does not lift the limit), so the budget route refuses 0 or
negative and points to account blocking; grant amounts above 1e12 tokens are
refused (a typo'd approval once set 6.7e12 = de-facto unlimited); accounts created
before the budget feature had no envelope at all and are repaired on read.

## The Admin configuration tab

Runtime-adjustable settings, no restart needed:

| Setting | Where | Notes |
|---|---|---|
| Default token limit | **Admin → token limit** | writes `KEY_MAX_BUDGET` / `KEY_BUDGET_DURATION` for new and existing accounts |
| Per-user / per-group quotas | **Users** | precedence: user override → group → global default |
| Model catalog | **Admin** | add/edit/remove chat, OCR and voice models; launch and stop the served model |
| Media sidecars | **Admin** | start/stop each sidecar independently of the chat model |
| Maintenance mode | **Admin** | blocks non-admin traffic everywhere without stopping any backend — see [operations](operations.md#maintenance-mode) |
| Email config & test | **Admin** | `GET /admin/email/config` (never returns the password) and `POST /admin/email/test` |
| Platform status card | **Admin** | free disk, backup age, monitor incidents, served model and the portal's counters |

Admin actions answer JSON with an honest status (`ok/error`, `warning` on partial
success, an HTTP code that matches what happened) — see
[development → the admin action contract](development.md#code-conventions).
